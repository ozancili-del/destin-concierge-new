## Third-campaign focus

### Persisted-state integrity

- Changing arrival, departure, adults, children, or total guests invalidates old booking, flight, and activity URLs.
- Repeating identical trip details preserves valid verification.
- Preferred-unit-only changes do not unnecessarily invalidate date availability.
- Saved booking links are rejected for malformed/future timestamps, missing queries, malicious hosts, mismatched dates, unavailable units, nonnumeric party parameters, or mixed valid/malicious arrays.
- Valid, recent, server-generated booking verification can still be resent.

### Cross-round action safety

- Lead capture, maintenance alerts, owner relays, and owner-chat invitations are suppressed if repeated in a later model round of the same guest turn.
- A pre-agent maintenance/emergency backstop prevents the model from sending a second alert.
- Read-only tools remain callable in later reasoning rounds.
- Per-round and per-turn tool limits remain enforced.

### Generated orchestration coverage

- Every non-empty combination of Weather, local guide, activity, unit facts, and business knowledge is executed in forward and reverse order.
- Twenty-four date/party scenarios run a sequential `remember_booking_details` → `check_availability` flow.
- Non-object, null, scalar, array, and unusual tool argument payloads do not crash the loop.
- Empty, null, reasoning-only, unsupported-content, missing-name, and unknown-tool model envelopes recover through correction or fallback.
- Duplicate read-only call floods from one through twelve requests execute the external lookup only once.

### External-service chaos

- Hung fetches abort.
- Discord content is bounded, HTTP/network failures are reported, and owner-chat invite failures remain honest.
- Weather rejects malformed schemas and invalid days instead of manufacturing 0°F facts.
- Fractional and whole-number precipitation formats are normalized and clamped.
- OwnerRez responses missing the expected booking collection now return unknown rather than falsely available.
- Malformed active booking rows make availability unknown; malformed canceled rows do not block inventory.
- Invalid availability and flexible-window inputs make no network calls.
- OwnerRez retry and partial-unit failure behavior are verified.
- Price-drop boundaries, snapshot HTTP/JSON/network failures, HMAC exactness, and malformed Sheets cells are tested.

### Security and factual permissions

- BLUE confusable Unicode and separator variants remain gated.
- Invented phone numbers and email addresses are rejected; verified or user-supplied contacts are allowed.
- Numeric and word-form prices and percentages require verified support.
- Natural day-month wording is allowed only when backed by verified ISO dates.
- Broader phrases such as “Unit 707 has an opening” are treated as availability claims and require a positive live result.
- Tool and webpage content is explicitly treated as untrusted data, not instructions.
- The admin phrase triggers only when the entire trimmed message is `lets go mf`, not when embedded in a normal guest sentence.

## Defects discovered and fixed in campaign three

1. Consequential actions could repeat in a later model round of the same turn.
2. Trip changes could leave stale booking, flight, or activity URLs authorized.
3. Corrupted persisted booking verification could contain mixed valid and malicious links.
4. OwnerRez HTTP success with a missing/wrong booking-array schema could be treated as open inventory.
5. Malformed active OwnerRez records could fail open.
6. Malformed Weather records could become fake 0°F forecasts.
7. Precipitation values were not robust to fractional versus whole-number formats.
8. Invalid flexible-window inputs could reach date arithmetic/network paths.
9. Admin snapshot HTTP, JSON, or network failures could escape the service adapter.
10. The admin phrase could be triggered as part of a longer sentence.
11. Structured snapshot failures exposed `reason`, while the handler displayed only `error`.
12. Natural `5 January` output could be falsely rejected because the month-first matcher partially consumed a four-digit year.
13. “Unit 707 has an opening” was not recognized as an availability claim.
14. Unicode-confusable secret-code text, invented contacts, and word-form commercial claims needed broader normalization.
15. Booking cancellation/date/property normalization needed stricter fail-closed handling.

## Limitation

The **947 offline tests were run and passed**. They validate the implemented loop, deterministic rules, state integrity, service adapters, generated tool combinations, malformed model responses, permissions, and HTTP endpoint with scripted model outputs and mocked connectors.

The **56-case live-model routing benchmark was not run here** because no OpenAI API key was available. Offline testing cannot prove that every future model snapshot will select the ideal tools for every unseen guest phrase. Run the live benchmark and controlled staging integration tests before broad production cutover.
