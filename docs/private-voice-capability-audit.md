# Private Voice capability audit — 2026-09-12

Scope: source-backed comparison of the preserved legacy Voice gateway and its Chat fallback against the local ordered-memory candidate. No paid model requests, live service queries, microphone tests, production edits or external writes were made.

## Baseline and limits

The legacy snapshot is the parent of c239889 (before the protected web preview). The replay records its full SHA and SHA-256 of executeTool in RAW-REPLAY.json. That function is byte-equivalent to the preserved current implementation after newline normalization; later optional runtime injection changes occur outside it. This is an actual legacy tool comparison, not a reconstruction.

Legacy Voice routes through pages/voice-lab.js and falls back to /api/destiny-chat with the last 20 browser history messages. pages/api/destiny-chat.js:5 selects chat-agent.js only when NEXT_PUBLIC_DESTINY_AGENT_V3 is true; otherwise it selects chat.js. Both branches were inspected. The deployed production flag was not queried, so the tool replay certifies the preserved agent-v3 path only, not the active production configuration or live end-to-end Chat quality.

Legend: supported means implementation evidence exists; deterministic evidence is named where executed. “Not yet verified” is not a pass. The candidate remains disabled and local; “candidate supported” does not mean deployed.

## Executed replay and interpretation limits

RAW-REPLAY.json has 14 complete dual-arm tool/state cases: every input, typed fixture, expected behavior, output, resulting state and controlled service trace. Eight cases returned success in each arm; six intentionally returned unavailable/clarification/denied statuses, with contract-specific names. This is completion of a deterministic harness, not a 14/14 semantic or naturalness score.

SCRIPTED-TRANSCRIPTS.json contains all three actual executor replies for the split-date/party/correction fixture. Those replies were supplied by a scripted model stub. They prove preservation and adapter identity, not live model understanding.

Initial replay errors were harness defects: the legacy service fixture omitted fetchPriceDrops, and two candidate activity calls omitted outcome_id. Both were corrected without changing business code. The original raw replay is retained as RAW-REPLAY-incomplete-fixtures.json. A source-pattern recording test was updated to require the new no-recording guard. Failed TAP runs are preserved separately; original paid evaluation fixtures/results were not changed.
